Questions and answers

About the project

What problem does your system solve?
A paper register or a shared spreadsheet cannot tell a student whether a book is in, when theirs is due, or how to get one that is out. It cannot keep a fair queue, work out a fine, or tell a librarian what to do today. The Campus Library does all of that in a small system a student can understand.
Who uses it?
Two roles. Members search, place holds, renew and see what they owe. Librarians run the desk, handle holds and the hold queue, fines, titles, copies and members, and read the reports.

Technology and architecture

Why PHP and MySQL?
They run on a free local server (XAMPP), need no installation on the user's computer, and are widely used. The goal was a system a student can read line by line, so no framework was used.
How does a request travel through your code?
The page includes functions.php, which starts the session, connects to the database and runs release_due_holds(). require_role() checks who is asking. A form (POST) is checked for its secret code, the rule runs inside run_rule(), a message is saved and the browser is redirected. Otherwise the page reads its data and prints.

Database

Why separate tables for books and copies?
A hold is for a title (any copy will do). A loan is for one physical copy with its own barcode and status. One table with a copies number could not say which copy is out, who has it or when it is due.
Why is copy status stored, but overdue is not?
A copy's status changes only when a librarian acts, and the desk reads it constantly. Overdue depends on today's date and changes by itself, so a stored flag would be wrong by morning. It is worked out from the due date.

Rules

What makes a member blocked?
An overdue loan, or unpaid fines of Rs 100 or more. A blocked member cannot borrow, renew or place holds, but can still return books, because returning is how they get unblocked.
How is the late fine worked out?
Days late times Rs 5, never more than Rs 200 for a loan. A book returned on its due date is not late, and every calendar day counts.

Security and privacy

How are passwords stored?
Only as a hash made by password_hash(), checked with password_verify(). Someone who reads the database cannot read the passwords.
How do you stop SQL injection?
Every query with user input is a prepared statement. The input is sent separately from the SQL, so it can never change what the query does. A test searches for ' OR '1'='1 and finds nothing.
