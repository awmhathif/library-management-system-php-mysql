Library Management System kit

Common errors and fixes

Find your message, read the cause, apply the fix. If none fits, copy the last step folder that worked into htdocs/library-management-system and carry on from there.

1. Apache will not start in XAMPP

Port 80 in use, or 'Port 80 in use by another program'.

Fix. Another program uses the port (Skype, IIS or another web server). Close it and press Start again. If you cannot, open Config, then Apache (httpd.conf), change Listen 80 to Listen 8080, restart Apache, and use http://localhost:8080/library-management-system/.

2. MySQL will not start in XAMPP

Port 3306 in use, or MySQL shutdown unexpectedly.

Fix. Another MySQL is running (check Windows Services and stop it), or XAMPP was closed badly. Close XAMPP, reopen it as Administrator, and Start MySQL again.

3. The page shows code, not the website

You see <?php require ... as text.

Fix. The file was opened as a file (the address starts with file:///) instead of through Apache. Use http://localhost/library-management-system/... and make sure Apache is running.

4. 404 Not Found for a page you made

The requested URL was not found on this server.

Fix. The folder or file name is different from the address. Check htdocs/library-management-system. On Windows, Notepad can save test.php as test.php.txt. Turn on File name extensions in File Explorer to see it.

5. Blank white page

Nothing at all, no error.

Fix. PHP found an error but hides it. Open xampp/apache/logs/error.log and read the last lines. Usually it is a typo. You can also add ini_set('display_errors', 1); as the second line of functions.php while you learn, and remove it later.

6. Parse error

Parse error: syntax error, unexpected ...

Fix. A missing semicolon, quote, bracket or brace. The line number in the message is where PHP noticed, so look at that line and the line above it. Compare with the box in START-HERE, or copy the file from the last step folder.

7. Failed to open stream

require(includes/functions.php): Failed to open stream: No such file or directory

Fix. The file name or folder is spelled differently. The folder must be called includes and the files must match exactly, in lowercase.

8. Headers already sent

Cannot modify header information - headers already sent by (output started at ...)

Fix. Something was printed before a redirect. Look at the file named in the message: remove any blank line or space before <?php, and make sure the page does all its work before it includes header.php.

9. Access denied for user

SQLSTATE[HY000] [1045] Access denied for user 'root'@'localhost'

Fix. The database login in includes/config.php is wrong. XAMPP's default is user root and an empty password. If you set a password in phpMyAdmin, put it in DB_PASS.

10. Unknown database

SQLSTATE[HY000] [1049] Unknown database 'library_management'

Fix. The database is not created yet. In phpMyAdmin, Import database.sql (step 1).

11. Could not find driver

PDOException: could not find driver

Fix. PHP cannot talk to MySQL. In XAMPP, open Config, then PHP (php.ini), make sure the line extension=pdo_mysql has no semicolon in front, save and restart Apache.

12. Call to undefined function

Fatal error: Call to undefined function block_reason()

Fix. A page uses a function that is not in functions.php yet. You skipped some new lines of this step. Compare functions.php with the step box, or copy it from the step folder.

13. Undefined array key or variable

Warning: Undefined array key "title"

Fix. A name is spelled differently in two places (for example the form field and the PHP). Look at both and make them identical.

14. Bad request

The page says only: Bad request.

Fix. A form was sent without its secret code, or the session was lost. Reload the page that has the form and try again. If you copied a form, make sure the line with csrf_field() is inside it. Browsers that block cookies break this.

15. You are logged out straight away

You log in, click a link, and are asked to log in again.

Fix. The session cookie is not kept. Allow cookies for localhost, or try another browser. Make sure session_start() is at the top of functions.php.

16. My change does not show

You saved, but the page looks the same.

Fix. Press Ctrl and F5 to reload without the browser's saved copy. Check you saved the right file (VS Code shows a dot on a tab with unsaved changes).

17. The dates are a day wrong

'Due today' on the wrong day.

Fix. Set your timezone in config.php (date_default_timezone_set). The system uses PHP's date for everything except the demo data, which is counted from the day you import.

18. The demo data looks old

Loans that should be late are not, after some days.

Fix. Demo dates are counted from the day you imported database.sql. Import it again to start the demo fresh.

19. A member cannot collect their held book

Check out says 'on the hold shelf for another member' for the right person.

Fix. This is the hold trap. ready_hold() must have status = 'ready' in its query. Old Expired and Cancelled holds still point at the copy. Compare with step 8.

20. Phone cannot open the site

The site opens on the computer but not on your phone.

Fix. Use your computer's address, not localhost: http://192.168.x.x/library-management-system/ (run ipconfig on Windows to find it). The phone must be on the same Wi-Fi, and the firewall must allow Apache.

21. Sinhala or Tamil titles show as strange letters

A title like Gamperaliya shows as à¶... or question marks.

Fix. The file was read with the wrong character set. database.sql starts with SET NAMES utf8mb4; so that every import tool reads it as UTF-8. Make sure that line is still there, then import the file again.

22. Buttons act without asking first

Withdraw, Mark paid or Cancel hold happen straight away, with no box.

Fix. assets/app.js is not loaded. The last line of includes/footer.php must be <script src="assets/app.js"></script> and the file must be in the assets folder. Press Ctrl and F5. The server still checks every action, so nothing unsafe happens without the box, but the box protects against a wrong click.

23. Import fails in phpMyAdmin

#1044 Access denied, or the import stops with an error.

Fix. Use the Import tab at the top level of phpMyAdmin (not inside a database), and pick database.sql from the folder. The file starts by creating the database itself, so you do not need to create one first.
