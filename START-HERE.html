Before you start

Get your computer ready

Goal: by the end of this chapter XAMPP and VS Code are installed, Apache and MySQL are running, and you have an empty library-management-system folder.

You do not need to know programming to start. This chapter installs two free programs and checks that they work. It takes about 20 minutes, most of it waiting for downloads.

What you are going to build

A website for a campus library. It has two kinds of users:

  • Members (students) search the catalogue, place a hold on a book that is out, renew their loans, and see what they owe. They only ever see their own books.
  • Librarians run the desk: they check books out and in, hand held books to the next person in line, manage the queue for a book, collect or waive fines, add books and copies, see every member, and read a monthly report. A librarian can add another librarian. Nobody can make themselves one.

The library runs on a few simple rules. They live in one file, so you can change a number and the whole system follows.

RuleValue
A loan lasts14 days
Books a member can have out5
Renewals per loan2 (each renewal gives 14 days from that day)
Holds a member can have at once3
Time to collect a held copy3 days
Late fineRs 5 a day, never more than Rs 200 for one loan
Blocked from borrowingwhen a loan is overdue, or unpaid fines reach Rs 100
Lost bookRs 800

Plain PHP and MySQL, 6 tables, about 1,200 lines of PHP in total. It works on a computer and on a phone. There are no libraries to install and no pictures to download: even the book covers are drawn with CSS.

1. Install XAMPP

XAMPP gives your computer a web server (Apache), PHP, and a database (MySQL, called MariaDB inside XAMPP). Download it free from apachefriends.org and install it with the default choices.

  1. Open the XAMPP Control Panel.
  2. Click Start next to Apache and next to MySQL. Both names turn green.
  3. Open a browser and go to http://localhost/. You should see the XAMPP welcome page.
  4. Go to http://localhost/phpmyadmin/. This is the page where you look at the database. Leave it open in a tab.

If Apache will not start, another program is usually using the same port (Skype and some printer tools do). Close it and try again. Your common-errors page has the exact messages and fixes.

2. Install VS Code

VS Code is a free editor for writing code. Download it from code.visualstudio.com. It colours the code so mistakes are easy to see.

3. Make the project folder

Everything you build goes inside XAMPP's htdocs folder, because that is the folder Apache shows on the web.

  1. Windows: open C:\xampp\htdocs. Mac: open /Applications/XAMPP/htdocs.
  2. Make a new folder called library-management-system. Inside it make two more folders: includes and assets.
  3. In VS Code choose File, Open Folder and pick library-management-system.

4. Test that PHP works

In VS Code make a new file inside library-management-system called test.php with this one line, and save it:

How this guide works

  • There are 11 steps. The site works after every step. Each step adds one real feature.
  • Each step shows the files to create or change. Lines with a green bar and the word new in the box heading are the lines added in that step. Press Copy, paste into the file, save.
  • Every step ends with a Check it works list. Do not move on until it is true.
  • The steps folder has one file you always need: steps/step-01/database.sql, imported in step 1. Apart from that, use it only when stuck: it holds the whole project exactly as it should be after each step. Copy the last step that worked into htdocs/library-management-system and carry on.

Step 1

The database and the first page

Goal: the database exists with its demo data, and the home page shows live numbers from it.

Everything a library does is keeping track of things: which books exist, who has them, who is waiting, who owes money. So we start with the database. Get this right and the pages are easy.

The big idea: a title is not a copy

A library owns Atomic Habits once as a title, but may own it twice as physical copies. Each copy has its own barcode and its own status. So there are two tables, books (titles) and copies. A member places a hold on a title. A librarian checks out a copy.

3. includes/functions.php

Every page will start by including this file. For now it holds the basics:

  • db() opens one database connection. q(), rows(), row() and val() run a query and give back all rows, one row, or one value. They use prepared statements: the ? marks are filled in separately, so what a visitor types can never become SQL.
  • e() makes text safe to print on a page. Always use it on anything that came from the database or a form.
  • Date helpers: today(), add_days(), days_between(), nice_date(), and due_words() which turns a due date into "Due tomorrow" or "5 days late".
  • flash() keeps one message for the next page. csrf() makes a secret code that every form carries, so another website cannot send a form for your user.
  • me() finds the logged in user (nobody can log in yet, so it gives nothing).
  • nav_link() prints one link of the top bar, and marks it when it is the page you are on, so you always know where you are.

Say it in your viva

Why are titles and copies separate tables? A hold is for a title (any copy will do), but a loan is for one physical copy. One row per title with a "copies" number could not say which copy is out, who has it, or when it is due.

Why is a copy's status stored but "overdue" is not? A copy's status is a small state machine that changes only when a librarian does something, and the desk reads it all the time. "Overdue" depends on today's date, so it changes by itself every midnight. A stored overdue flag would be wrong by morning, so we work it out from the due date whenever we need it.

  • In phpMyAdmin change a copy's status to lost, reload the home page, and watch the shelf count drop by one. Change it back.

Step 3

Search the catalogue

Goal: anyone, even logged out, can search by title or author, filter, and open a book page that shows if it is on the shelf.
